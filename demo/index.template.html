FAIL

A routine blocked by the usage limit is not recorded as “Skipped — usage limit” with its slot and reset time, and it does not catch up after usage returns. Public help, the docs, and the changelog through v0.68.1 do not show that setting or that history row.

This page is a draft simulation. It does not clear the fail. Nothing here spends a usage pool.

The draft below is what a catch-up would write in history, and how the queue would behave, if the owner later says to build it. Existing routines stay off. Turning catch-up on starts at the latest skipped run only.

Evidence and the per-case grade are in RECEIPT.md. The draft help entry is Catch up a routine after a usage limit. Primary live pages: Routines, Skills and routines, Changelog, staff reply, 13 Sep 2026.

Repeat it from this page

  1. Read the fail banner. That is the live grade. The green words under each case mean the draft simulation held, not that Grok Bot does this.
  2. Open each case and read the history label, the slot, and the reset time.
  3. On the bench, leave Weekday digest on Off. Record a usage-limit skip, press Weekly reset, then Run queued catch-ups. History keeps the skip and says catch-up is off. The chat stays empty.
  4. Set that routine to Latest skipped run only. Record two skips. Weekly reset, then run the queue. One report is titled with the later slot.
  5. Set Hourly digest to Each skipped slot and Standup to Latest skipped run only. Record four skips on Hourly digest and one on Standup, then Weekly reset. The plan starts are 90 seconds apart. Run queued catch-ups. One queue, several start times.
  6. For the near-fire case, set Next fire to 10 minutes after the reset, record a skip, and release usage. History says superseded by scheduled run.
  7. Fire while paused, with the computer down, or with the gate false. Those labels are not “Skipped — usage limit,” and a later reset does not report them.
  8. Turn on “Usage closes before the catch-up runs,” release usage, and run the queue. The row says held, and it is not done. Clear that switch, press Plan top-up, and run once more.

What gets written when the limit blocks a fire

The fire does not run and does not post. History gains Skipped — usage limit, the slot in the routine's time zone, and the reset time that was seen. If the signal has no reset time, the row says unknown.

Catch up after usage resets

SettingAfter usage is available
OffThe skip stays in history. The routine waits for its next slot. This is the existing-routine default.
Latest skipped run onlyOne catch-up, for the newest open usage-limit skip. This is the default when the setting is turned on.
Each skipped slot (up to 3)One catch-up per open skip, at most 3, newest first.

Weekly reset, a plan top-up, or raising the limit can start the queue. The report title is Catch-up for the original slot. A stay-quiet-on-NONE instruction stays quiet. A catch-up that should have posted and produced nothing is not marked done.

What does not catch up

Paused, computer down, and owner-gate skips do not enter the queue. A next fire within 15 minutes writes superseded by scheduled run. Pause or delete after the skip drops the queued work. An edit runs the current prompt and keeps the original slot on the label. Starts are 90 seconds apart across bots. If the catch-up hits the limit, the same slot is held until a later signal.
